# E-UAE ReAction (AmigaOS 4.1 PPC) – Changelog

Base: E-UAE 0.8.29-WIP with the ReAction GUI ("e-uae-reaction").
Items marked **[core]** touch the CPU/FPU emulation; everything else is GUI / platform.

## Unreleased (after v17)

- **Fix: start from the Workbench icon.** Double-clicking the E-UAE program icon (no config icon) showed the ASL requester "select config" (leftover of the original E-UAE) and quit on Cancel, so the GUI never opened. It now starts like the Shell without arguments (GUI opens, current dir = PROGDIR:). Start with a config icon (`sm_NumArgs == 2`) and Shell start with arguments are unchanged. (`od-amiga/main.c`)

## v17 – CD32: Akiko chip from WinUAE (CD-ROM controller, C2P, NVRAM), CD32 ROMs, CD32 pad, CD32 model preset
**Release version: E-UAE 2.0.0, ReAction GUI 1.0** (the v numbers in this file stay the internal build numbers). `configure` / `configure.in` now report 2.0.0 (`$VER: E-UAE 2.0.0`, window title, `config_version=` and savestate version); was 1.0.0. About window: "E-UAE 2.0.0 - ReAction GUI 1.0".
Core and GUI. **Run `sh configure …` again and `make clean` before building**: `configure` now builds `akiko.c` with `-DCD32` (new option `--disable-cd32`; needs AGA and the CD-ROM image drive), and `options.h`, `memory.h`, `akiko.h`, `cdimage.h` changed. New config keys, named as in WinUAE: `cd32cd=`, `cd32c2p=`, `cd32nvram=`, `cd32nvram_size=` (KB, default 1), `cd_speed=` (percent, default 100, 0 = as fast as possible); `flash_file=` (existing key) is the NVRAM file. Old configs load unchanged.

- **[core] Akiko, ported from WinUAE `akiko.cpp`** (new `akiko.c`, replaces the E-UAE 0.8.29 version, which was never built for AmigaOS 4 and did not match the CD32 ROM's drive protocol):
  - **CD-ROM controller:** Chinon O-658 drive protocol as in WinUAE – command and status rings by DMA (TX/RX positions, TXDMADONE / RXDMADONE), PIO access at `$B80028`, commands STOP, PAUSE, UNPAUSE, PLAY/READ, LED, SUBQ, INFO (firmware string `CHINON  O-658-2 24`), checksum and unknown-command errors, TOC entries one per CD frame (each three times, as the real drive), play start / play end / play error notifications, media status after a disc change. Data DMA into the 16 blocks of the data area (bit 15 first, sector counter in byte 3, raw sector without the first 4 bytes, error field zeroed), at single / double speed with WinUAE's seek delay, subcode DMA (double buffer, `$FFFF0000` end mark) for data and audio, interrupt INT2 (level triggered: re-asserted every line while `INTREQ & INTENA`). The CD data thread of WinUAE prefetches 128 sectors (two buffers, swapped under the Akiko semaphore); WinUAE's count of sectors to read at the end of a data track is one short and re-read the sectors already copied from the old buffer – both fixed.
  - **Drive:** the CD-ROM image drive of v16 (`blkdev-cdimage.c`: ISO, CUE/BIN with audio tracks). New high-level functions `cdimage_hl_*()` – TOC in WinUAE's layout (A0, tracks, A1, A2), raw 2352-byte sectors (sync and header generated for 2048-byte images), CD-DA play / pause / stop / volume, audio status and position, Q sub-channel generated from the position as WinUAE does for images without sub-channel data – used instead of WinUAE's blkdev layer. CD audio goes through the existing mixer. The audio status is polled by the Akiko thread (WinUAE: callback); not right after a request, so a stop followed by a new play is not taken for the end of the old play.
  - **Disc change:** the GUI change (eject now, insert a second later) is seen by the media check (every 2 seconds, as WinUAE); a swap that falls between two checks is reported as removal plus insert (change counter of the drive), and the status packet reports the state the check saw – so multi-disc games notice the new disc. The media status packet of WinUAE read the drive live and could report "disc present" twice.
  - **C2P:** chunky-to-planar converter at `$B80038` (Mequa's algorithm from WinUAE; host test against the reference algorithm).
  - **NVRAM:** 24C08 I2C EEPROM (WinUAE `flashrom.cpp`: bit-banged I2C at `$B80030`/`$B80032`, page writes, sequential reads). Saved in `flash_file=`, default `PROGDIR:cd32.nvr` (created when missing). The file is opened for every write and closed again (WinUAE keeps it open), so game saves are on disk at once.
  - **Extended ROM delay loop patch** with a fast CPU (68030+, JIT, CPU speed not "original"), as in WinUAE, applied once.
  - **CIA-A TOD** on a CD32 ticks at the rate Akiko fakes (50/60 Hz, CONFIG bit 23) instead of the video mode; **CD audio mute** from CIA-A PRA bit 0 (the OVL pin of other Amigas), as in WinUAE.
  - Savestates: new chunk `CD32` (WinUAE layout); after loading, the TOC is read again, the C2P result rebuilt and CD audio resumed at the saved position.
  - Akiko is mapped as its own bank at `$B80000–$B8FFFF` (`memory.c`, registers mirrored every 64 bytes, upper 32 KB read 0) instead of the old check inside every CIA access in `cia.c`. Akiko is present when one of `cd32cd`, `cd32c2p`, `cd32nvram` is on (`cd32_enabled`, before: when a 512 KB extended ROM was loaded).
- **[core] CD32 ROMs** (`memory.c`): **1 MB CD32 ROM** (391640-03, Kickstart and extended ROM in one file) as Kickstart: the Kickstart is taken from the upper half, the extended ROM from the lower half (or the other way round if only the lower half starts with the Kickstart id `$1114`), as in WinUAE; a separate extended ROM file takes precedence. Before, the first 512 KB of such a file (the extended ROM) were loaded as Kickstart. A 512 KB extended ROM is mapped at `$E00000`; with `cd32cd=true` it is always taken as a CD32 ROM. A new extended ROM replaces the one of the last start (the old one was never freed); `memory_cleanup()` frees it.
- **[core] CD32 ROM mirrors** (`memory.c`, WinUAE `cs_ksmirror_a8`): with `cd32cd=true` the Kickstart is also mapped at `$A80000–$AFFFFF` and the extended ROM at `$B00000–$B7FFFF`, as on the real CD32. The CD32 ROM reads there at boot; before, these reads went to the CIA emulation (`cia_wget: unknown CIA address a83000 …` in the log).
- **Log:** the frame limiter no longer writes `framewait: min_sleep = … ms` (every change of its sleep calibration, about once a second) and `framewait overflow` (after resets and pauses). The calibration itself is unchanged.
- **Bugfixes and archives (v17, second part):**
  - **[core] LHA / LZH and LZX archives** are opened directly, like ZIP and GZ before (`zfile.c` had an empty `lha()` stub, LZX was unknown): new `archive_lha.c` with the LHa for UNIX decoder used by WinUAE (`lha_*.c`: -lh0- … -lh7-, -lzs-, -lz4-, -lz5-, header levels 0–2) and `archive_lzx.c` with WinUAE's unlzx decrunch code (merged blocks); the directory and extraction glue is new (E-UAE has no zvolume layer). Choice as for ZIP: `archive.lha/name.adf` or `archive.lha/#2` selects a file, otherwise the first file of a known type (disk image, ROM, …), otherwise the first file. Works everywhere images are opened (floppies, ROM, …); the floppy requesters now also show `.gz`, `.lha`, `.lzh`, `.lzx`. Hardening against damaged archives (the old decoders trusted the data): code lengths > 16, Huffman tables whose code sum wraps past 0x10000, pt_len/c_len counts beyond their arrays, tree nodes beyond the node arrays, LZX code-length deltas out of range, LZX buffers padded for the deliberate overruns of the decrunch code; decoding stops at the first bad table. LHa's global names are prefixed (`lha_x_…`) so they can't clash with E-UAE symbols. Host test (AddressSanitizer / UBSan): LHA archives made with jLHA (-lh0-, -lh5-, -lh6-, -lh7-, header levels 0 and 2, two 880 KB images and a text file) by default, by name and by number, byte-exact; a real Amiga LZX archive (from the XPK-ELZX test file of the ancient project, 152089 bytes) byte-exact; 840 damaged archives (truncated, overwritten bytes, flipped bits) without a crash or sanitizer report.
  - **GUI window stays open after Stop** (`main.c`): `do_exit_machine()` called `gui_exit()`, so the window was destroyed and built again at every Stop or close of the emulator window – back in the middle of the screen, first page, list selection lost. Now it is freed once at the end of the program.
  - **No "kick.rom" default** (`cfgfile.c`): the Kickstart field showed `kick.rom` at the first start, so the ROM folder of the Settings window was never used. The field is now empty; *Start* without a Kickstart shows a message instead of booting UAE's replacement ROM.
  - **"Save" while the emulation runs** (`main.c` `uae_save_config()`): saved `currprefs` (the running values) instead of the GUI values, so changes for the next start were missing; now always `changed_prefs`, like "Save as". The backup `.uaerc~` was only made the first time (AmigaDOS `rename()` does not replace an existing file); the old backup is now removed first, and a failed write puts the old file back.
  - **Model presets set the IDE interface** like real hardware (A500+/A600 and A1200: Gayle, A4000: A4000 IDE, A500 and CD32: none), also without an IDE drive; drives already on IDE keep their interface. Removing the last IDE drive no longer switches the interface off.
  - **Display options removed that the AmigaOS 4 graphics backend never read:** *Color mode* (the depth comes from the screen), *Refresh rate*, *Sync with screen* (Display page) and *Hide mouse pointer in emulator window* (Input page; the pointer is always hidden in the active emulator window). The config keys stay and are kept in configurations.
  - `quick_insert()` (hotkey "insert disk"): the requester title was built with `sprintf()` into 48 bytes; a longer translation overflowed the stack. Now `snprintf()` into 128 bytes.
  - Catalog: `MSG_HINT_MEDIA_DFFILE` changed, new `MSG_SET_496` (496 messages).
- **Iconify, middle mouse button, cartridge (v17, third part):**
  - **GUI can be iconified** (`gui_core.c`): iconify gadget in the title bar of the GUI window (window.class with an AppPort); the window becomes an icon on the Workbench (`PROGDIR:E-UAE.info`, else `PROGDIR:uae.info`, else the default tool icon), double-click brings it back, as do the GUI hotkey and Stop. New setting *Iconify the GUI after Start* in the Settings window (group *Window*, default on, `iconify_on_start=` in `PROGDIR:E-UAE.prefs`).
  - **[core] Middle mouse button releases the pointer** (`gfx-amigaos/ami-win.c`): in a window on the Workbench the middle button ends the mouse grab (Ctrl+Alt+G), shows the Workbench pointer and activates another window on the screen (the backdrop window, if any), so the emulator window gets no more input; a click into the window continues. The Amiga then gets no middle button; in full screen it gets it as before. Checkbox *Middle mouse button releases the pointer* on the Input page, config key `amiga.middle_release=` (default true).
  - **Cartridge field on the Media page** for Action Replay 1/2/3 ROM dumps and HRTMon (`cart_file=`, already supported by `ar.c`; until now only settable in the configuration). Ctrl+Alt+F (*Freeze*, Shortcuts page) opens the cartridge. Only changeable while the emulation is stopped.
  - Catalog: new `MSG_SET_497…504` (504 messages).
- **[core] bsdsocket.library emulation, call layer rewritten** (`bsdsocket.c`, `od-amiga/bsdsock.c`, new `od-amiga/bsdsock_proxy.h`; `od-amiga/thread_emu.c` and `thread_socket.h` removed). Reported: crashes of the host task `socketbase_thread` inside Roadshow, e.g. when starting WHDLoad games from Workbench (WHDLoad 18.1+ checks for updates over the network at every start; `NoNetwork` switches that off).
  - Every Amiga SocketBase still has its own host process with its own Roadshow SocketBase, but calls are now messages owned by the caller: the process no longer replies to a message the caller may already have reused (race), no MsgPort leaks per call, no Amiga code is called from the host process (hostent/servent/protoent are copied in the host process and written into Amiga memory by the trap).
  - Amiga socket numbers are the Roadshow numbers of that SocketBase. The old global table (1024 entries, Amiga number used as index without a range check, free entries marked with host socket 0) is gone; WaitSelect() got sockets of other programs and socket 0 for every free entry.
  - **Blocking calls no longer freeze the emulation:** `accept`, `connect`, `send`, `sendto`, `recv`, `recvfrom`, `WaitSelect`, `CloseSocket`, `gethostbyname`, `gethostbyaddr` let the calling Amiga task `Wait()` on its socket signal while the host process works; it is woken through `uae_Signal()` (EXTER interrupt of the filesys board, which is now also present with `bsdsocket_emu` alone). Before, the whole emulated Amiga stopped while e.g. a program waited for data or a DNS answer. Break signals (`SetSocketSignals`, `SBTC_BREAKMASK`, default CTRL-C) abort the call with EINTR, and the signal mask of `WaitSelect()` works (was ignored). A SocketBase used by another task than the one that opened it falls back to the old blocking behaviour.
  - CloseLibrary waits until the host process has really ended (closing its Roadshow base closes all its sockets). Reset and Stop now end all host processes (`bsdlib_reset()` was empty: after a reset the old processes kept running with pointers into Amiga memory of the old session) and drop queued Amiga signals of the old session (new `native2amiga_reset()`).
  - Wrong calls fixed: `getpeername` called `getsockname`; `getsockopt` passed `optval` as `optlen`; `getservbyname` called `gethostbyaddr`; `gethostbyaddr`, `getservbyname/port`, `getprotobyname/number` returned host pointers (or nothing) to the Amiga; `accept` returned an unrelated value; `ReleaseCopyOfSocket` was missing.
  - `SocketBaseTagList`: TAG_MORE/TAG_SKIP lists are followed on the Amiga side (Roadshow got Amiga addresses), GET values are written back into the Amiga tags, error-string tags return Amiga strings (Roadshow returned host pointers), break/event masks stay Amiga-side, the errno pointer tags are converted, hooks and callbacks are refused.
  - Amiga pointers handed to Roadshow are checked (`valid_address()`); invalid ones become NULL (EFAULT) instead of a host crash. Removed: the jmp written into the level 6 vector at every boot (grew the rtarea).
  - **No more freezes of the whole emulation** (tester report: IBrowse in QEMU, E-UAE and its GUI hung while the OS4 Workbench kept running): every call that can wait now waits only in the calling Amiga task, on a signal allocated for that call in that task (before: the signal of the task that opened the library - a SocketBase used by another task fell back to letting the emulation wait). Short calls (socket, setsockopt, ...) still run directly when a worker is free; if all are busy they are queued like blocking calls instead of holding up the emulation.
  - Parallel workers per SocketBase (Roadshow base shared with `SBTC_CAN_SHARE_LIBRARY_BASES`, up to 8 processes) are built in but switched off (`BSD_PARALLEL 0` in `od-amiga/bsdsock.c`): in the first test E-UAE froze as soon as IBrowse started - most likely Roadshow serialises the calls of a shared base, so a short call waited behind a `WaitSelect()` of another worker while the emulation waited for it. With one worker per base, short calls run directly only when it is idle; everything else waits in the calling Amiga task. `SBTC_CAN_SHARE_LIBRARY_BASES` reports TRUE to Amiga programs (every call waits on a signal of the calling task).
  - **Hang of E-UAE after network activity** (tester, QEMU: after IBrowse had downloaded and unpacked a file, the GUI and the emulation stopped while the OS4 Workbench kept running): a call is broken by signalling the worker, and that was CTRL-C. But the worker also calls `uae_Signal()`, whose E-UAE semaphores (`td-amigaos/thread.c`, used by the comm pipes) take a pending CTRL-C as "interrupted" and go on without the lock. When the small native2amiga pipe was full, a left-over CTRL-C let the worker write into the full pipe; the pipe got out of step and the emulator thread waited for data that never came. Roadshow is now told to break on CTRL-E (`SBTC_BREAKMASK`), the workers are aborted with CTRL-E, and the signal is cleared before every call and before waking the Amiga task.
  - The worker processes do not use newlib at all (exec memory via `AllocVec`/`FreeVec`, own string helpers): it is a plain AmigaOS process, and newlib's per-task data of a process that used newlib and ended could leave a stale entry that crashed later newlib calls of other E-UAE threads (tester report after the first rewrite: "UAE thread" crashed in `newlib.library.kmod`, list walk into 0xABADCAFE, when starting a WHDLoad game).
  - Still not supported: `sendmsg`/`recvmsg` (Amiga pointers inside `struct msghdr`), `GetSocketEvents`, `getnetbyname/addr`, syslog.
- **[core] 48000 Hz sound works** (`sd-amigaos/sound.c`): `init_sound()` refused every rate where 3546895 / rate < 80 (a limit taken from Paula's period, meaningless for the output to the host), so 48000 Hz from the Sound page silently became 22000 Hz ("Can't use sound with desired frequency 48000 Hz" in the log). Now 8000-96000 Hz are accepted; anything else falls back to 44100 Hz.
- **[core] Yellow colours after fullscreen and back** (`gfx-amigaos/ami-win.c`, reported by two testers on real hardware): `init_true_colors_output()` switched the byte swap on for the 16-bit PC formats (R5G6B5PC, R5G5B5PC) but never off. After a 16-bit PC screen (e.g. the fullscreen screen on a Radeon, Ctrl+Alt+S) the next 32-bit ARGB window kept it: every colour was `bswap_32`-ed (blue lost, red and green swapped, white became yellow) until E-UAE was restarted. Also affected the RTG CLUT conversion. The flag is now reset for every new output.
- **[core] uaescsi.device missing from the second start on** (`scsiemul.c`, bug since v16): `scsidev_install()` wrote the device code only once per program run, but `rtarea_init()` clears the rtarea and the trap table at every start of the emulation (`do_preinit_machine()`). After Stop (or closing the emulator window) and Start, OpenDevice of uaescsi.device failed (e.g. "Cannot open uaescsi.device unit 0" from CacheCDFS); only quitting E-UAE helped. The code is written at every start again.
- **[core] CD-ROM drive on Akiko:** with `cd32cd=true` the drive is always attached to Akiko and present also without `cdimage0=` (a CD32 always has its drive); uaescsi.device, the ATAPI drive at IDE and the built-in CD0: file system leave it alone (the CD32 extended ROM mounts CD0: itself).
- **[core] CD32 pad:** with `cd32cd=true` the joystick in Amiga port 1 is a CD32 pad (`inputdevice.c` already had the pad; now decided from the prefs, as `cd32_enabled` is only set at the next reset). Joystick buttons 1–7 = red, blue, yellow, green, forward, reverse, play.
- **GUI, Hardware page:** new model preset *CD32 (AGA, 2 MB, Akiko)* (68EC020, AGA, 2 MB chip RAM, Akiko with CD drive) and checkbox *CD32 Akiko chip (CD drive, C2P, NVRAM)* in the chipset group (only with AGA; switching to OCS/ECS turns it off). Model presets now also compare the Akiko setting (an A1200 with Akiko shows *Custom settings*).
- **GUI, Hard disks page:** CD controller *CD32 (Akiko)* (switches the Akiko chip on, like the checkbox; another controller or *Remove* switches it off); the drive list shows *CD32 (Akiko)* and *CD0:*; the boot options are greyed out for Akiko (the CD32 boots its CD itself). *Media* page: the CD group is usable as soon as Akiko is on; tooltip of the extended ROM explains the CD32 ROMs. Input page: tooltip of port 1 explains the CD32 pad buttons.
- **About:** "ReAction GUI v17", credit line "ReAction GUI and extensions (v1 - v17) by Falke_34".
- Catalog: texts `MSG_HINT_INPUT_PORT1`, `MSG_HINT_MEDIA_EXT`, `MSG_HINT_HARDWARE_MODEL`, `MSG_CD_440`, `MSG_SET_486` changed, new `MSG_SET_492…495` (German in `deutsch.ct`); regenerated with `tools/mkcatalog.py` (495 messages).
- Not included (as before): the CD32 FMV module (Video CD), CD+G graphics (images have no sub-channel data), Akiko's CIA chip select quirk.
- Status: all changed files syntax-checked against the AmigaOS 4 SDK headers with the flags of a newly configured tree (`-DCD32`, and the predefined `amiga`/`amigaos`/`AMIGA` macros); compared with v16, no new errors or warnings in any core or GUI file. Host test of the real `akiko.c` + `blkdev-cdimage.c` with a CUE image (data track + two audio tracks), driven like the CD32 ROM's cd.device: initial media status, INFO, media status after init, TOC (all six points three times, data / audio control, MSF), data DMA of 16 sectors compared with the image (block order, header byte, data, timing), CD-DA play with start notification, SUBQ (track, index, position), play end notification after mixing, LED with response, checksum error reply, NVRAM write / sequential read over I2C and the file content, C2P against the reference algorithm, disc swap seen as removal + insert. Built by the user and run in QEMU (AmigaOne): CD32 boot screen without a disc, CD32 Demonstration Disc (CUE/BIN) boots, menu, CDXL animation "Flight" and CD audio work.


## v16 – built-in uaegfx.card, RTG hardware pointer and VBLANK, faster RTG output, 128 MB graphics memory, real fullscreen switches, CD-ROM images (uaescsi.device or ATAPI, bootable as CD0:)
Core, graphics output and GUI. **Run `sh configure …` again and `make clean` before building**: `configure` now builds the SCSI/CD part, `picasso96.h`, `options.h`, `blkdev.h` and `scsidev.h` changed and the build has no dependency tracking (see LIESMICH.txt). New config keys `gfxcard_hardware_sprite=` (default true) and `gfxcard_hardware_vblank=` (default false), named as in WinUAE, and `cdimage0=`, `cdimage0_controller=`, `cdimage0_boot=`, `cdimage0_bootpri=`; old configs load unchanged.

- **[core] Built-in uaegfx.card** (`picasso96.c`, after WinUAE `uaegfx_card_install()` / `inituaegfxfuncs()`). The card is now a library in the boot ROM area: a Resident (RTF_AUTOINIT) behind the ROMTags of the filesys DiagArea (`filesys_diagentry()` → `uaegfx_add_resident()`) creates `uaegfx.card` 3.5 at boot. rtg.library finds it in memory, so the `uaegfx.card` file from the Picasso96 package is no longer needed (an existing one is simply not loaded). Needed on the Amiga side: Picasso96 (rtg.library) and the monitor file `DEVS:Monitors/UAEGFX`.
  - `uaegfx_install_code()` (called after `rtarea_init()` in `main.c`) writes the 68k code once per start: one stub per BoardInfo function slot (35 slots). Blitter functions return to the Picasso96 default function when the emulation does not handle a call (`d0 = 0`), as in WinUAE. `InitCard()` of the built-in card (BoardInfo in a0) fills the slots, the flags (BLITTER unless NOBLITTER is set in the monitor tooltypes, NOMEMORYMODEMIX, GRANTDIRECTACCESS, INDISPLAYCHAIN, HARDWARESPRITE, VBLANKINTERRUPT) and the clocks / limits, and builds the mode list as before.
  - Library base layout as in WinUAE (`CARD_*` in `picasso96.h`). The init routine of the library fills the card fields and installs a VERTB interrupt server (`AddIntServer`) from 68k code, so no extended traps are needed.
  - The filesys board (and with it the DiagEntry) is now also present without any mounted drive when graphics card memory is configured (`expansion.c`), as in WinUAE where RTG enables the boot ROM. The boot ROM's unit loop handles 0 units.
  - The old uaelib hooks (functions 16–40) stay for the card file; while the built-in card is active they are ignored with a log line (as in WinUAE). New uaelib function 40 = BlitRectTransparent.
  - All BoardInfo function slot offsets added to `picasso96.h` (taken from WinUAE `picasso96_win.h`; all 171 offsets and flags the two headers share were checked to have the same values), plus the missing BIF_ flags.
- **[core] Hardware mouse pointer** (SetSprite, SetSpritePosition, SetSpriteImage, SetSpriteColor; normal, hires and big sprites, after WinUAE). The emulation only keeps image, colours and position; `gfx-amigaos/ami-win.c` builds a 32 bit ARGB pointer bitmap when the image or the colours change, and `comp.c` (`BackFill_Sprite()`) composites it over the RTG picture after the normal composite, with the same scaling. The RTG picture buffer itself is never changed. The Amiga pointer position comes from the emulation (the host pointer is hidden in the window and the mouse is relative), so the pointer is always at the right place. On an 8 bit host screen (no composite) the card does not offer a hardware sprite and Picasso96 uses its software pointer (log line). Option *Hardware mouse pointer* (`gfxcard_hardware_sprite`, default on).
- **[core] VBLANK interrupt of the card** (SetInterrupt, BIF_VBLANKINTERRUPT): `picasso_trigger_vblank()` runs in `vsync_handler()` (`custom.c`) right after the VERTB request; the card's VERTB server then calls `Cause()` on the SoftInterrupt of the BoardInfo. Before, `WaitVerticalSync` was only a stub and there was no card interrupt. Option *Vertical blank interrupt* (`gfxcard_hardware_vblank`, default off as in WinUAE).
- **[core] BlitRectTransparent** (new): copies all pixels whose colour differs from the transparent colour, compared as stored in Amiga memory without the alpha / padding bits; overlapping source and destination in one bitmap handled. Also the fixed board functions of WinUAE: ResolvePixelClock, GetPixelClock, CalculateMemory, GetCompatibleFormats; SetClock, SetMemoryMode, SetWriteMask, SetClearMask, SetReadPlane, WaitVerticalSync, WaitBlitter as `rts`; ScrollPlanar, UpdatePlanar and DrawLine go to the Picasso96 defaults.
  - Not offered (flags stay off, slots untouched): VGA screen split (SetSplitPosition), palette / DAC switch (CoerceMode, GetCompatibleDACFormats) and the video window features (Create/Delete/Get/SetFeatureAttrs). The OS4 output always shows one bitmap from `picasso96_state.Address`; split or dragged screens and YUV overlays would need a new output path.
- **[core] Graphics card memory up to 128 MB** (`main.c` `fix_options()`, GUI list 64 / 128 MB). **Fix:** `expamem_init_gfxcard()` only wrote a size for 1, 2, 4 and 8 MB; 16 and 32 MB boards were announced as 8 MB, so AmigaOS could place the next board into the upper part of the graphics memory. More than 8 MB now uses the extended Zorro III size table, as the Z3 fast memory does.
- **Real fullscreen switches** (`gfx-amigaos/ami-win.c`). *Fullscreen (Amiga modes)* opens an own screen for the Amiga display; *Fullscreen (Picasso96 modes)* opens an own screen while the Amiga shows an RTG screen. Unchecked, the *Screen type* applies. When the Amiga switches between its display and the graphics card, `gfx_set_picasso_state()` reopens the display if the other kind of screen is wanted ("Ask at startup" never opens the requester there); an own RTG screen that is smaller than a new RTG mode is reopened in a fitting size. Before, *Fullscreen (Picasso96 modes)* did nothing and *Fullscreen (Amiga modes)* only chose the output size.
  - **Fix, fullscreen gadget / hotkey** (`toggle_fullscreen()`): it set the screen type to *Ask* for good, so every toggle opened the screen mode requester and there was no way back to the window. Now it switches between a window and an own screen (mode chosen automatically) until the emulation is restarted.
  - `graphics_setup()` registered `atexit (graphics_leave)` on every start of the emulation; now once.
- **[core] Faster RTG output** (`picasso96.c`, `gfx-amigaos/ami-win.c`). The display was slow until a Workbench with background picture and dock was built up:
  - **Changed lines once per frame:** every change of the framebuffer line by the CPU (`flush_write()`) locked the host bitmap, copied that one line and unlocked it again – one `LockBitMap()`/`UnlockBitMap()` pair per line. Now the changed byte range of each visible line is only remembered and all changed lines are copied with **one** lock at the end of the frame (`p96_flush_dirty()` from `picasso_handle_vsync()`). The fall-back paths of fill and blit (no host blit / fill) are deferred the same way. Before a host blit (`DX_Blit`, its source is the host bitmap) the remembered lines are copied first; `SetPanning` and mode switches flush or drop them. The Amiga framebuffer stays the only source of the picture. Host test: 100,000 random writes in 20 frames gave 20 locks instead of one per changed line, picture identical (16 bit, 8 bit CLUT on a 16 bit host, panning offsets).
  - **Composite only on change:** the whole window was composited every frame, also for a static screen. Now only when the picture changed, the mouse pointer moved or changed, the window was opened, resized, refreshed or activated, the screen was switched, and once a second as a safety net.
  - **JIT:** reads of the graphics card memory are no longer marked "special" and `gfxmem_bank.baseaddr` points to the framebuffer, so translated code can read it directly; writes still go through `gfxmem_*put()` (line tracking). Effective only with *comp_trust* "direct" / "indirectKS" / "afterPic" – the default "indirect" handles all memory accesses through the bank functions anyway. With a "direct" setting the whole screen is copied once a second, in case a translated block wrote into the framebuffer past the line tracking (before, such a write went to a wrong host address).
- **[core] CD-ROM drive with ISO and CUE/BIN images** (new `blkdev-cdimage.c`, `include/cdimage.h`). One CD-ROM drive, attached either to `uaescsi.device` unit 0 (`scsiemul.c`, already in E-UAE but never built for AmigaOS 4) or as **ATAPI drive at the emulated IDE interface** (Gayle A600/A1200 or A4000, master or slave, `gayle.c`) – like the IDE hardfiles. Images only, no host drives: on AmigaOS the block device layer (`blkdev.c`) now uses the image drive instead of `od-amiga/blkdev-amiga.c`.
  - **ATAPI** (`gayle.c`, after ATA/ATAPI-5 and WinUAE `ide.cpp`, PIO only): packet device signature `14 EB` after reset / diagnostics / DEVICE RESET, IDENTIFY DEVICE aborted with signature, IDENTIFY PACKET DEVICE (CD-ROM, removable, 12-byte packets, accelerated DRQ), PACKET command with interrupt reason (CoD/IO), data-in in DRQ blocks of the byte count limit, data-out phase for MODE SELECT, status phase with the sense key in the error register; the SCSI command itself runs in `blkdev-cdimage.c` (`cdimage_scsi_cmd()`), the sense data stays for REQUEST SENSE. ATA read/write commands are aborted. DRDY is clear after reset / DEVICE RESET and set with IDENTIFY PACKET DEVICE or PACKET (packet devices, ATA/ATAPI-4/5), no DSC – before, the status always showed DRDY|DSC like an ATA disk, and Kickstart 3.2 did not offer the drive in the boot menu. With that, Kickstart 3.2 finds the drive (IDENTIFY PACKET, INQUIRY, TEST UNIT READY, READ CAPACITY, RDB search in blocks 0–15, checked with a temporary command log); it does not mount a CD itself – booting from CD is done by the built-in CD file system (below). A hardfile and the CD on the same IDE position: the hardfile wins (log line). Needs a `scsi.device` with ATAPI support on the Amiga side (Kickstart 3.1.4 / 3.2, or a patched driver); the Kickstart 3.1 one only knows ATA disks. Host test with the real IDE code: signature, IDENTIFY abort, IDENTIFY PACKET, INQUIRY, READ CAPACITY, READ(10) in 2048-byte DRQ blocks and 20 blocks in one go, error with sense key 5 + REQUEST SENSE, READ TOC, MODE SELECT (data-out) / MODE SENSE, disc change with unit attention 6/28, ATA read aborted.
  - Images: ISO (2048 bytes per sector; raw 2352-byte images are detected by the sync pattern), CUE sheets with BIN files: `MODE1/2048`, `MODE1/2352`, `MODE2/2336`, `MODE2/2352`, `AUDIO`, several `FILE` entries, `INDEX 00/01`, `PREGAP`, `POSTGAP`. LBA 0 = INDEX 01 of track 1. A `FILE` name is tried as given, relative to the cue sheet and as bare name next to the cue sheet (cue sheets from other systems often carry foreign paths). 64-bit file access (`open64`/`lseek64` on newlib), so DVD-size ISOs work.
  - SCSI-2 / MMC command set of a CD-ROM drive: TEST UNIT READY, REQUEST SENSE, INQUIRY (type 5, removable, ANSI 2, VPD 0/0x80), MODE SENSE/SELECT 6/10 (pages 0x01, 0x0D, 0x0E audio volume, 0x2A capabilities), START STOP UNIT (eject), PREVENT ALLOW, READ CAPACITY, READ 6/10/12, SEEK, READ TOC formats 0/1/2 (LBA and MSF, also the old ATAPI format field), READ SUB-CHANNEL (position, MCN, ISRC), READ HEADER, READ CD / READ CD MSF (all header / user data / EDC field combinations, sector type check, C2 and sub-channel as zeros), PLAY AUDIO 10/12/MSF/TRACK INDEX, PAUSE/RESUME, STOP, GET EVENT STATUS NOTIFICATION, GET CONFIGURATION, READ DISC INFORMATION; write commands report "write protected". Sense codes: not ready 2/3A without a disc, unit attention 6/28 once after a disc change, illegal request 5/20, 5/21, 5/24, 5/64. `HD_SCSICMD` with autosense; `scsi_SenseActual` is now written as UWORD (`blkdev-amiga.c` wrote a byte to the high half).
  - `uaescsi.device` (`scsiemul.c`): new `TD_GETGEOMETRY` (DG_CDROM, removable), `TD_EJECT`, `TD_READ64` / `NSCMD_TD_READ64`, `TD_SEEK64`, `NSCMD_DEVICEQUERY` (command list in the rtarea); `CMD_READ` reads the image blocks directly with 64-bit offsets. **Fixes:** `dev_exit()` aborted `d_request[i]` (the unit index) instead of `d_request[j]`; after the last `CloseDevice()` a new `OpenDevice()` could find the unit thread still "running" while it was leaving and queue requests to it – the next open now waits for the old thread (as does `dev_exit()`); `CMD_GETNUMTRACKS` used the size from the reset. The device code was appended to the rtarea on every start of the emulation (~300 bytes and 12 traps each time); it is now written once. The device is started with `scsi=true` or as soon as a CD-ROM drive is configured (`scsidev_enabled()`), and the filesys board (DiagEntry with the Residents) is then present without mounted drives too (`expansion.c`).
  - Disc change while the emulation runs: the GUI changes `changed_prefs.cdimage[]`, `cdimage_vsync()` (once per frame from `vsync_handler()`) applies it in the emulator thread. Without sound output the position advances by time, so programs still see the play progress and the end of a track.
  - Locking: SCSI commands come from the unit threads, mixing and disc change run in the emulator thread; one exec SignalSemaphore per drive. The disc change notification is sent after the drive lock is released (no lock order problem with `change_sem` of `scsiemul.c`). Buffers live in the drive structure, not on the 16 KB stack of the unit threads.
  - **Booting from CD – built-in CD file system** (new `filesys_cdfs.c`, `include/filesys_cdfs.h`, like WinUAE's "CDFS automount"): with the option *Boot from CD* the drive is also mounted as read-only UAE file system unit **CD0:** with a boot node (boot priority, default -127 as in WinUAE) – it appears in the boot menu, also without a disc, and boots with any Kickstart; on the Amiga side no CD file system or mount entry is needed. E-UAE reads the ISO 9660 file system of the disc itself (levels 1–3, Rock Ridge names when present, volume name from the primary volume descriptor). `filesys.c`, `fsdb.c` and `fsdb_unix.c` work with POSIX calls on host paths; `filesys_cdfs.h` redirects these calls, and paths below the unit's root `@UAE-CD@` are served from the image (open/read/lseek/close, stat, access, opendir/readdir, get_fs_usage; everything that writes returns "read-only"), all other paths go to the host as before. The unit is added only to the running mount list (not to the configuration); the filesys board is present for it without other drives. A disc change while the emulation runs is seen by new file accesses (files opened on the old disc report a read error), the volume name stays until the next reset (E-UAE's file system units have no removable volumes). Host test: Rock Ridge and plain ISO images made with pycdlib (names, case-insensitive paths, sub-directories, reads across block boundaries, seek, end of file, write refused, missing files, disc change, no disc = empty root "CD-ROM"). Kickstart 3.2 itself does not mount a CD from an ATAPI drive (it only searches an RDB), the same as WinUAE without "CDFS automount".
  - Config: `cdimage0=` (drive present; empty value = drive without disc), `cdimage0_controller=uaescsi|ide0|ide1` (ide0 = master, ide1 = slave; the interface type comes from `ide=`), `cdimage0_boot=true|false`, `cdimage0_bootpri=` (default -127). Tested at uaescsi.device with CacheCDFS of the OS 3.9 emergency disk (OS 3.9 CD read correctly). No DOSDriver files are shipped.
  - Build: `configure` builds `scsiemul.c`, `blkdev.c` and `blkdev-cdimage.c` with `-DSCSIEMU` (new option `--disable-cdimage`); `Makefile.am/.in` list the new files.

## v15 – CPU list with FPU, JIT soft flush, cycle-exact rules, blank disks / hardfiles, double frame output, config loading, hotkeys
Core and GUI. Config file format is unchanged (`cpu_type=`, `comp_flushmode=`, `cachesize=`, `cpu_cycle_exact=`).

- **GUI, CPU list:** new entries *68EC020 + 68881 FPU (24 Bit)* and *68020 + 68881 FPU (32 Bit)* (`cpu_type=68ec020/68881`, `68020/68881`, cpu_level 3). Before, a config with one of these types was shown as *68020 (32 Bit)* and the FPU was **silently removed** on *Start*. The mapping prefs → list (`cpu_value_from_prefs()`) also handles combinations that are not in the list (68000/68010 with 32 bit, 68040/68060 with 24 bit) instead of falling back to 68020. *68020 (24 Bit)* is now labelled *68EC020 (24 Bit)*.
- **[core] JIT soft flush:** `flush_icache()` always threw away the whole translation cache, so *Hard cache flush* (`comp_flushmode=hard|soft`) had no effect. With *soft*, a CPU cache flush (CACR clear bit, CINV, CPUSH) now keeps the translated code: active blocks are marked for a checksum test and are translated again only if their 68k code has changed. Kickstart ROM blocks are not checked. *hard* (the default, `comp_hardflush=1`) behaves as before.
  - Changes of the memory mapping (`map_banks()`, Picasso96 on/off switch) always flush hard (`flush_icache_hard()`), because the translated code contains 68k addresses. `flush_icache_hard()` is declared in `newcpu.h` (no-op without JIT).
  - `check_checksum()`: a block found unchanged is moved back to the active list (otherwise the next soft flush would not check it again and stale code could run); a changed block is invalidated before it is recompiled.
  - Block length for the checksum: it ended at the *start* of the last instruction, so its extension words were not covered. Now min/max over all instructions (with `comp_constjump` the history is not linear) plus `LONGEST_68K_INST` (24 bytes, new in `compemu.h`). Blocks with a backward constant jump are never trusted on a soft flush.
  - `invalidate_block()` clears length and checksums (blockinfos live in the uninitialised code buffer).
  - Tooltip of *Hard cache flush* describes both modes.
- **[core] JIT and cycle-exact (as in WinUAE):** the JIT loop ignores *Compatible* and the cycle-exact CPU core, but `cpu_cycle_exact` still switched the chipset to exact interrupt / chip RAM timing (also with a 68020+, where it is not "68000 only" as assumed earlier). `fix_options()` now turns the JIT off if a config enables both (log message; `changed_prefs.cachesize` is cleared too, otherwise `check_prefs_changed_comp()` would allocate the cache again). Compatible + JIT only gives a log note.
- **GUI, hardware rules:** while the JIT is active (cpu_level ≥ 2 and a cache size), *Compatible CPU mode* and *Cycle-exact CPU* are greyed out and cleared; choosing a JIT cache clears them. Without 32-bit addressing the JIT cache is set to *Off* (it is greyed out there and would otherwise keep running unseen). Tooltips of CPU, Compatible and Cycle-exact updated (cycle-exact: full for the 68000, chip RAM and interrupt timing only for 68020+).
- **GUI, blank disks:** new button *New...* per floppy drive on the *Media* page. It creates an empty disk image with a save requester (`.adf` is added if there is no extension) and inserts it into the drive, also while the emulation runs. 3.5" DD / HD: formatted OFS disk (880 KB / 1760 KB), volume name = file name (max. 30 characters); 5.25": unformatted extended ADF. An existing file is only replaced after a Yes/No request; an image that is inserted in a drive is refused. The button is disabled while the drive type is *Off*. New helper `ra_confirm()` (`gui_util.c`).
- **GUI, Hard disks page redesigned:** the page now only has a drive list with the columns *Device*, *Type*, *Size*, *Controller*, *Path* and the buttons *Add directory...*, *Add hardfile...*, *Edit...* (also double-click) and *Remove*. Everything else is in two own windows; the main window is locked while one is open (empty Intuition requester via `Request()`/`EndRequest()` plus busy pointer), requesters open over the dialog (`ra_req_window` in `gui_util.c`).
  - *Hardfile window:* path with file requester, info line (size, partition table found or not), controller *UAE (uaehf.device)* / *IDE A600/A1200 (Gayle)* / *IDE A4000* with *Master* / *Slave*, *Read only*; group *Advanced* with device name, boot priority, RDB mode and geometry (only for UAE, geometry only without RDB). A file with RDB is detected when chosen.
  - *New image* in the hardfile window: size (MB) and file system, *Create...* makes an empty hardfile and uses it for the drive. Creation as in `make_hdf` (`make_hdf.c`): geometry 32 sectors / 1 head / 2 reserved blocks, heads and then sectors raised while there are more than 65535 cylinders (FFS before OS 3.9), file size matching the geometry; extended by seeking to the end and writing one byte, otherwise filled with zeros (64 KB chunks). Idea from WinUAE (`CreateHardFile()`): the file system's DosType is written to the first 4 bytes (OFS/FFS: 0, PFS3 `PFS\0`, PDS3 `PDS\0`, SFS `SFS\0`, RDB: marker `RDSK` = empty disk for HDToolBox). Overwrite request, files already used by a drive are refused, busy pointer, a partly written file is deleted on error, limit 2047 MB while `off_t` is 32 bit (newlib on AmigaOS 4, as in `make_hdf`). RDB detection also accepts the bare `RDSK` marker.
  - *Directory window:* path with drawer requester, volume name (taken from the directory name if empty), *Read only*; *Advanced*: device name, boot priority.
  - Device names (DH0, DH1, ...) are assigned automatically (first free name); paths already used by another drive are refused.
  - The IDE interface (`cs_ide`) is no longer a separate choice: it follows the controller of the IDE drives (both share one interface) and is switched off when the last IDE drive is removed. Config keys unchanged (`ide=`, `ide0_hardfile=`, ...).
  - The rows of UAE units are built by the GUI instead of `sprintf_filesys_unit()`, which numbered the units by list position ("DH0:" for the first unit, whatever its name) and knew the hardfile size only while the file was open – after Start/Stop the list showed "size 0 Mbytes". Sizes now come from the file (`stat()`).
- **[core] `disk_creatediskfile()`** (`disk.c`) now returns 1 / 0 and logs write errors (was `void`, failures were silent); the volume name is limited to 30 characters (was an unbounded `strcpy` into the root block); the chunk buffer holds a full raw track – for an HD drive the extended ADF read 25 KB from a 16 KB buffer (also used by `disk_setwriteprotect()`).
- **Fix, display output / speed:** `is_vsync()` in `gfx-amigaos/ami-win.c` did not only answer "vsync mode?" but presented the frame (Picasso96 conversion + `BackFill_Func()` = CompositeTags over the whole window). The core calls `is_vsync()` as a query in several places: once per frame in `vsync_handler()` and again in `do_flush_screen()` (`drawing.c`) whenever no line of the frame changed. With a static picture and *Show LEDs in picture* off, every frame was therefore composited twice. With the JIT and CPU speed *Maximum* the 68k only gets the host time left over in the frame, so this made the emulation up to ~8x slower (SysInfo under QEMU: 2019 instead of 16533 Dhrystones; with the LED line on, lines change every frame and the second composite did not happen). The output is now `amiga_gfx_present()` (declared in `gfx-amigaos/gfx.h`), called exactly once per frame from `vsync_handler()` after `vsync_handle_redraw()`, so the last lines of a frame are shown in the same frame; `is_vsync()` just returns 0. Present since before v1 (not caused by the v15 changes).
- **Fix, loading a configuration** (`main.c`): *Load...* on the *Configuration* page did nothing. `uae_restart()` stored the chosen file in `restart_config[]`, but that buffer was only used as a flag "read the config again" – `parse_cmdline_and_init_file()` always read the default file, so the old settings came back. And while the emulation was stopped (GUI waiting at start-up) `uae_restart()` caused no state change at all, so the waiting loop never noticed the request. Now the chosen file is loaded: while running or paused on the restart (`restart_explicit`), while stopped directly in the waiting loop (`pending_config[]`, `load_pending_config()`), in both cases from the default settings and followed by `gui_open()`, which writes the values into all gadgets. If the file can't be read, the previous config file is loaded again (log message). *Save* still writes to the default config file, *Save as...* to any file. Present since before v1 (not caused by the v15 changes).
- **Fix, Amiga model after loading** (`page_hardware.c`): the *Preset* (A500, A1200 + turbo card, ...) is only a template that sets CPU, chipset and memory; it is not a config key. Its values were saved and loaded correctly, but after loading (or Start/Stop) the chooser always showed *Custom settings*. `write_prefs()` now recognises the model from the values (`model_from_prefs()`): if CPU, chipset, chip, slow and fast RAM match a model exactly and there is no Z3 / graphics card RAM, that model is shown.
- **Fix, slow RAM 256 KB** (`page_hardware.c`): the list offered 256 KB, but `fix_options()` only accepts 0, 512 KB, 1 MB and 1.8 MB and set it to 0 on start. The entry is removed.
- **Fix, graphics card RAM** (`page_hardware.c`): the list offered 64 and 128 MB, but `fix_options()` only accepts up to 32 MB and set larger values to 0 on start (the RTG card then disappeared without a message). The list now ends at 32 MB. A config with a larger value shows *None*, like the core uses it.
- **Fix, hotkeys did not work as shown on the *Shortcuts* page** (`gfx-amigaos/ami-win.c`, `hotkeys.c`, `od-amiga/main.c`). Present since the original AmigaOS 4 port, not caused by the v15 changes.
  - `remap_scancode` (`od-amiga/main.c`) deliberately swaps Alt and the Amiga / Windows key for the emulated Amiga (so Amiga+M etc. reach the Amiga instead of AmigaOS 4). The hotkeys were checked *after* this swap, so the default *Ctrl + Left Alt + Q* really was Ctrl + **left Amiga/Windows key** + Q, and the real Alt key did nothing. The modifier keys (0x60–0x67) of a hotkey are now checked by their physical key; other keys still use the remapped code (e.g. Home = Help). What the emulated Amiga receives is unchanged.
  - Order of the modifiers: `match_hotkey_sequence()` required the keys exactly in table order (Ctrl, then Alt, then the key); *Alt + Ctrl + Q* did nothing. Now the modifiers may be pressed in any order, the key comes last. Releasing one modifier only clears that key (before, it also cleared all following keys of the sequence). If several hotkeys match, the longest wins (*Ctrl + Alt + Shift + R* = hard reset, not soft reset).
  - Right Windows / right Amiga key was mapped to 0x64 (*Left* Alt) instead of 0x65 (*Right* Alt), against its own comment, so no key produced Right Alt. Fixed in both remap tables.
  - After a hotkey, the release of the modifier keys was not passed to the emulated Amiga (the whole key-up went to the hotkey), so e.g. Ctrl could stay pressed inside the Amiga. Keys whose press reached the Amiga now always get their release (`hk_key_sent[]`).
  - Tooltip of the modifier boxes (MSG_SC_323) now says "any order"; catalog regenerated.
  - Tested on the host with the real `hotkeys.c` and remap table: Ctrl+Alt+Q in both orders, release order, Ctrl+Boing+Q (no longer a hotkey), soft / hard reset, Right Alt (AltGr), no stuck keys.
- **Save as... adds `.cfg`** (`page_config.c`): a name without extension (e.g. *Amiga1200*) is saved as *Amiga1200.cfg*; a name with its own extension (*.uae*, *.conf*) is kept. If the file with the added extension already exists, a Yes/No request asks before replacing it.

## v14 – Hard disk page: one drive list, RDB hardfiles
GUI only (`page_harddisk.c`, catalog files). Config file format is unchanged (`hardfile=` / `hardfile2=`, `ide=`, `ide0_hardfile=`, `ide1_hardfile=`), old configs keep working.

- **Fix:** a hardfile with RDB (partition table, e.g. a Workbench image prepared with HDToolBox) could not be added through the unit list. The *Sectors* gadget accepted only 1…1024, so *Add hardfile* always created a plain hardfile with the default geometry (32 / 1 / 2) and the RDB header was mounted as file system data. E-UAE only treats a hardfile as RDB when sectors = 0 (`is_hardfile()` in `filesys.c`).
- **RDB detection:** when a file is chosen (or added), the first 64 KB are scanned in 512-byte steps for an `RDSK` block (length field 16…128 longwords). If found, the new checkbox *Hardfile has RDB (partition table)* is set, sectors / heads / reserved are passed as 0 and the geometry fields are greyed out. An RDB image is always mounted as RDB, even if the checkbox is cleared.
- **One list for all drives:** the unit list now shows UAE units (directories, hardfiles) and IDE hardfiles together, with the columns *Controller* and *Drive*. IDE hardfiles used to be missing from the list.
- **Controller per unit:** new *Controller* choice in the *Unit* group: *UAE (uaehf.device)*, *IDE master*, *IDE slave*. For IDE the fields that do not apply (device, volume, geometry, boot priority) are disabled. *Change* can move a hardfile between UAE and IDE; an occupied IDE slot is refused with a message; directories cannot be attached to IDE.
- **IDE interface:** the separate group *IDE controller (Gayle)* is replaced by a single choice *IDE interface* (None / A600/A1200 (Gayle) / A4000 IDE) below the list. Adding an IDE hardfile while the interface is *None* switches it to Gayle. IDE rows are marked when the interface is off.
- Catalog: new texts `MSG_*` 340…352 (German in `deutsch.ct`), `locale_ids.h`, `locale_defs.c` and `deutsch/E-UAE.catalog` regenerated with `tools/mkcatalog.py`. The old IDE group texts stay in the catalog (unused) so existing IDs are not renumbered.

## v12–v13 – IDE controller emulation (Gayle / A4000 IDE)
Chipset / peripheral emulation, so not tagged **[core]**. The two archives are listed together because only v11 and v13 were compared.

- **New `gayle.c` + `include/gayle.h`:** reduced C port of WinUAE `gayle.cpp` / `ide.cpp` (Toni Wilen). Emulates the Gayle IDE interface of the A600/A1200 and the A4000 IDE interface (mapped at `$DD2000`). One IDE channel with up to two ATA hard disks (master / slave) backed by host files through `hdf_open()` / `hdf_read()` / `hdf_write()`. The Kickstart's own `scsi.device` drives it, no extra driver is needed.
- Limits compared to WinUAE: host I/O is synchronous (no IDE thread); no ATAPI, no PCMCIA card (status registers report an empty slot), no IDE splitter, no savestates.
- Hooks: `memory.c` calls `gayle_reset()` and `gayle_map_banks()` after the custom, clock and mbres banks (it overrides parts of them); `custom.c` calls `gayle_hsync_handler()` from the hsync handler.
- Config options: `ide=none|a600/a1200|a4000`, `ide0_hardfile=`, `ide1_hardfile=`, `ide0_readonly=`, `ide1_readonly=` (`cfgfile.c`, `options.h`: `cs_ide`, `ide_hardfile[2][256]`, `ide_readonly[2]`); default is off.
- Build: `gayle.c` and `include/gayle.h` added to `Makefile.am` / `Makefile.in`.
- GUI: group *IDE controller (Gayle)* on the *Hard disks* page (controller choice, master / slave hardfile with file requester and read-only). Texts and tooltips are `MSG_*` 328…339, German translations included. (Replaced by the unified list in v14.)

## v11 – CPU core: exception frames and undefined flags (CHK, CHK2, DIVL, MULL)
Found with Toni Wilen's UAE CPU tester (68020 mode) and fixed against the WinUAE/FS-UAE reference behaviour.

- **[core] CHK (680x0):** undefined N/V/C flags are now set like real hardware, per CPU level (68000/010, 020/030, 040, 060), both when the exception is taken and when it is not (new helper `m68k_chk_flags()`). Fixes the CHK.L SR mismatch seen in cputest.
- **[core] CHK2 / CMP2:**
  - Stacked PC in the format-2 exception frame is now correct (PC is synced before the exception).
  - Undefined N flag (e.g. CHK2.B) now matches hardware (new helper `m68k_chk2_flags()`, port of WinUAE `setchk2undefinedflags`).
  - Carry calculation for the lower > upper case and for equality with a bound corrected.
- **[core] DIVL (DIVS.L / DIVU.L):** the instruction address stored in the format-2 frame of a divide-by-zero exception is now the instruction start (removed the stray `sync_m68k_pc()`).
- **[core] DIVL signed overflow:** `0x8000000000000000 / -1` handled without host overflow (quotient 0x7fff…, remainder 0).
- **[core] MULL (MULS.L / MULU.L):**
  - N/Z/V flags correct for 32-bit and 64-bit results.
  - Dh == Dl register order: 68040+ writes Dh then Dl, 68020/030 writes Dl then Dh (matches real CPUs).
- cputest verification: DIVS.W and DIVU.W pass (~12.7k tests each); CHK/CHK2/MULL/DIVL regression set added (`[test=FIXES]` in `cputestgen_68020.ini`).

## v10 – CPU / FPU core fixes
